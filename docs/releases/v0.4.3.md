# Turbo GreenVita 0.4.3

A settings release. 0.4.2 fixed latency; this one gives you two knobs for the
client itself — how much it logs, and how hard the link is allowed to push —
and fixes the touchscreen for everyone whose SDL build registered the touch
pads in the other order.

## Diagnostic logging is now a setting

Every diagnostic line the app prints used to go straight to the log, with no
way to silence it short of rebuilding. There is now one gate for all of them:
a new **Enable diagnostic logging** row in Settings, on by default, applies the
moment you toggle it.

The gate starts off while the app boots, so a fresh launch is silent until
settings load; toggling in Settings takes effect immediately, without a
restart. Every former `eprintln!` now routes through the same `elog!` macro,
so one switch silences the whole client.

## The streaming HUD no longer depends on the log

The green debug line on the Streaming screen ("Show streaming debug info")
reads its numbers from in-memory session state, never from the log, so it
keeps working with logging on or off. The two options are fully independent
and can be combined either way: HUD only, log only, both, or neither.

## Half-step bitrate caps

The **Max bitrate** setting gains **2.5, 3.5, and 4.5 Mbps** alongside the
existing options, so the full ladder is now 2, 2.5, 3, 3.5, 4, 4.5, 5, 6, 8,
and 10 Mbps. The value is advertised to xCloud in the client-capabilities
message when a stream starts — the same field and code path as before, just
with the extra rungs.

## The touchscreen selects games again

Tapping a title in the game list highlighted it fine on the builds the app was
developed against — and did nothing at all on others. The front and rear
touch pads were identified by hardcoded SDL device IDs, which are specific
to the SDL/VitaSDK build doing the registration, not to the hardware. When
the order differed, every front-screen tap was dropped before it reached the
UI: touch was dead, while the D-pad — polled directly from the controller —
kept working.

The pads are now identified from SDL's device names at startup ("Front" /
"Back"), with the historical IDs only as a fallback. The front pad remains
the only pointer source for both the UI and in-stream taps; unknown devices
are ignored while SDL enumerates them.

## Included from 0.4.2

- The input→photon round trip is measured (`ip:last/min`) and the input path
  tuned to 8 ms / 125 Hz — 161 → 27 ms on device
- No more keyframe probe; the render loop runs at 8 ms and shows the
  freshest frame
- Late frames are repaired, not discarded; audio time is no longer
  destroyed by the jitter buffer
- The A/V comparison is absolute, and the bitrate governor actually reacts
