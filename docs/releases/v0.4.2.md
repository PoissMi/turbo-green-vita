# Turbo GreenVita 0.4.2

Latency, measured properly this time. 0.4.1 fixed the upload path; this release
fixes the input path and the last unmeasured delay in the video path, and removes
the instrument that was hiding both.

## The input→photon round trip is now measured

`ip:last/min` is the time from a sampled controller change until the first picture
that could only have been captured after it lands. That is the server's half of the
loop — simulation, capture, encode, network — which no other number on the screen
covered: `in-lag` stops when the report leaves the client, and `kp` measured a
keyframe request, not an input.

**On device: 161 ms.** That is where the "character reacts half a second late" was,
and it is what the rest of this release attacks.

## The input report carries the newest state, not a batch

`InputQueue` batched 2–3 sampled controller states into one packet, and the server
reads the last one — the oldest state in the batch plus whatever was sampled in
between. That latency lived inside a single SCTP chunk, so no number on the HUD
could see it. The queue now holds exactly one frame, the freshest, and anything
older is superseded rather than batched: the server always acts on the freshest
state the client has.

## The controller is refreshed at the reference cadence

The send gate suppressed an unchanged frame for 16 ms, so `in-rate` read ~50/s —
and that was the refresh interval, not the wire. It is now 8 ms (125 Hz), the
cadence the reference client polls at, so the server is never acting on a state
more than 8 ms old.

**On device: `in-rate` 50 → 75/s, `ip` 161 → 27 ms.**

## No more keyframe probe

The probe fired a real keyframe request every 10 seconds to measure the picture's
round trip. On a 5 Mbps link a keyframe is a spike, so the stream hitched on the
cadence — and the hitch was being read back as the measurement. It is gone. The
picture's absolute age is now `pic`, which is `srv + age`, both already measured.

## The render loop can no longer drift against the server's clock

The loop deadline was 15 ms. At that cadence the loop slips against the server's
capture clock by up to a frame in complex scenes (`d/a` 6328/6508 µs against the
budget), and that slip is the drift that grows while you play. The deadline is now
8 ms, which bounds the phase error to half a frame.

## The display shows the freshest frame, not the oldest

The UI slot took the *oldest* frame still within the freshness limit, so a frame
waited in the slot while a newer one was already available. Handoff-to-upload
averaged 13.6 ms against a decode-to-handoff of 3.7 ms. Those waited frames were
never going to be shown — the render loop uploads one frame per iteration — so
they are now dropped before the pickup, and `ui_overwrites` still counts the drop.

**On device: `h>u` 13.6 → 9.7 ms average (31.6 → 18.5 ms worst).**

## The A/V comparison is absolute now

The earlier `av-lag`/`av-out` were measured against the *worst* alignment the
session had ever reached, so a picture half a second late showed up as a small
number. The reference is now absolute: the first video frame and the first audio
packet come from the same moment of the game, so the difference between their
arrival times is an origin-independent anchor that survives the two streams
carrying unrelated RTP timestamp origins.

## The audio path no longer destroys audio time

The RTP jitter buffer used to drop anything it could not assemble in time, and
every hole it left made the sound jump forward in game time — which is the
picture falling further behind what the player hears. The deadline is 40 ms and
the device queue is capped at 50 ms, so a late packet is held and a queue that
would overflow is bounded instead of growing without bound.

## The governor actually reacts now

The bitrate estimate backs off when the server's video timeline slips by more than
10 ms in a minute (was 25 ms), and recovers below 5 ms (was 8 ms). At 6 ms/min the
player already feels the picture getting older, and `kp:last` was climbing while
`drift`/`ld` sat below the old threshold.

## New HUD fields

| field | meaning |
| --- | --- |
| `ip:last/min` | input→photon round trip, in ms |
| `pic` | the picture's absolute age: `srv` + display age |
| `in-rate` | input reports per second leaving the client |
| `in-wire:<avg>/<max>us` | input report queued → out on the wire |
| `d>h/h>u:<avg>/<max>us` | decode→handoff and handoff→upload, average and worst |
| `a-del` | everything between the socket and the speaker, each stage counted once |
| `holes` | milliseconds of sound punched out of the timeline |


The input round trip is now 27 ms, the picture is 19 ms old, and nothing in the
pipeline drops, resets, or requests a keyframe.

## Included from 0.4.1

- Late frames are repaired, not discarded
- Every decoded frame reaches the screen
- The input channel is reliable and ordered again
- The input report carries a real uptime stamp
- The server's video delay is measured and the bitrate estimate follows it
- Deeper staging ring (5 NV12 slots)
- Audio buffering cut from ~180 ms to ~66 ms
